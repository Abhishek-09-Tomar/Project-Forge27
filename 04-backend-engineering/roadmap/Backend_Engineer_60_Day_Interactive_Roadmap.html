Flagship project: Wallet Intelligence Service

Core: authenticated REST API, double-entry PostgreSQL ledger, transactional outbox, Kafka and Redis. No model participates in financial decisions, writes or authorization.

AI: read-only explanations using verified transaction facts, help-desk RAG over synthetic FAQ documents, bounded tool calls and offline evaluation.

Architecture: Auth → AI gateway → tenant-scoped retrieval → provider adapter → local model. Validate every result; deterministic fallback if model unavailable. Keep AI outside the critical transaction path.

Milestones: day 20 fake-model tests; day 30 demo; day 37 read-only tools; day 48 evaluation and failure drill; day 60 portfolio audit.

Compatibility: retain Java 21 and Spring Boot 3.x for core work. Select Spring AI versions compatible with your Boot release using its official compatibility guidance. If a newer AI version needs a different Boot major, isolate it in a separate service or migrate deliberately. Never mix incompatible dependency versions.

AI engineering playground

Run deterministic, in-browser learning exercises without installing a model. These are simplified simulations of trusted application logic, not actual embeddings or language-model inference.

1 · Retrieval & tenant isolation

Experiment with a toy keyword retrieval system over synthetic documents. The selected tenant is a simulation of authenticated identity; a real server obtains identity from verified authentication, never a client field.

Inspect toy corpus and expected behavior

Scores count matching unique meaningful words; lexical retrieval is not vector similarity. Only authorized sources are ranked. Real RAG adds generation and independent grounding evaluation.

2 · Structured output validator

Edit a hypothetical model response. Application code requires a known status, nonempty explanation, and authorized citation IDs. This checks schema and policy only, not factual truth or semantic grounding.

Ready to validate.
Contract

Exact fields: status (ANSWERED or UNKNOWN), explanation (1–300 chars), citations (unique IDs). ANSWERED must cite at least one allowed ID. UNKNOWN must have no citations. Semantic truth requires separate evidence checking.

3 · Retrieval evaluation dashboard

Run six frozen synthetic cases at the selected top-k. Positive-query recall averages per-query relevant-document coverage. Unknown-query abstention here means zero retrieved hits, not model abstention. Check failures rather than optimizing only the aggregate.

Run to see results.

when 100 concurrent requests transfer 10.00 from A to B
then exactly 10 succeed
and A = 0.00 and B = 100.00
and every journal balances to zero
and 90 failures create no partial entries
and replay of successful idempotency key creates no extra transfer
